- **ADR-003:** Escolha do mecanismo de autenticação.
- **Contexto:** O sistema de reservas de salas permite que diferentes usuários, como alunos, professores e administradores, acessem funcionalidades específicas de acordo com suas responsabilidades. Para garantir a segurança das informações e impedir acessos não autorizados, é necessário implementar um mecanismo de autentificação que permita identificar os usuários e verificar suas credenciais durante o acesso ao sistema.
- **Alternativas:**
	- Autenticação por sessão: o sistema cria uma sessão no servidor após o usuário realizar o login, utilizando um identificador de sessão armazenado no navegador.
	- Autenticação utilizando Tokens: após realizar o login, o usuário recebe um token que seŕa enviado nas próximas requisições para comprovar sua requisição.
- **Decisão:** Será adotada a autenticação baseada em sessões, na qual o sistema criará e armazenará uma sessão no servidor após a validação das credenciais do usuário. Um identificador de sessão será utilizado para reconhecer o usuário nas requisições seguintes, permitindo controlar seu acesso às funcionalidades do sistema. 
A validação inicial de credenciais e vínculo ativo é delegada ao Sistema Central de Autenticação via IAutenticacaoService (ASR 4), mantendo-se localmente apenas a sessão autenticada do usuário no servidor web. 
- **Consequências:** 
	- **positivas:**
		- Simplicidade na implementação.
		- as sessões permitem identificar os usuários e controlar seus acessos de maneira centralizada. 
		- é possível invalidar sessões no servidor quando um usuário realizar logout ou quando sua conta precisar ser bloqueada. 
	- **negativas:**
		- Necessidade de armazenar e gerenciar as sessões dos usuários no servidor.
		- Consumo adicional de recursos para manter as sessões ativas.
		- Necessidade de implementar mecanismos de expiração e invalidação das sessões.
