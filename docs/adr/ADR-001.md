**ADR-001:** Escolha da arquitetura de software: monólito simples, modular ou microsserviços.  
**Contexto:** o sistema de reserva de salas é preciso oferecer serviços como; realizar a agenda de sala, visualização de suas agendas e dados das salas cadastradas. Como essas funcionalidades possuem responsabilidades diferentes, é preciso organizar o sistema em módulos diferentes, facilitando a manutenção e a evolução de cada funcionalidade. Além disso, o sistema precisa manter a sua estrutura simples, sem a necessidade de gerenciar diversos serviços independentes.  
**Alternativas:**
- Monólito: Manter a simplicidade do sistema para facilitação de manutenção.  (Mas como o sistema apresenta certas responsabilidades que precisam ser independentes, essa estrutura não seria adequado.)
- Monólito Modular: Além de manter a simplicidade de estrutura do sistema, organizar os serviços do sistema de forma independente.
- Microsserviços: Como o sistema apresenta serviços com responsabilidades diferentes, é preciso organizar os serviços de modo independente. Com isso, facilita a manutenção, evolução do sistema e adição de novos serviços.
**Decisão:** Será adotada a arquitetura Monólito Modular, por o sistema não possuir muitos serviços. Com isso, podemos manter a estrutura do sistema simples e organizar os serviços de forma independente.   
**Consequências:**
- **positivas:**
	- Facilitar a manutenção.
	- Baixo custo de implantação.
	- Menor complexidade de implantação e gerenciamento.
- **negativas:**
	- Um erro grave pode afetar todo sistema.
	- Necessidade de implantar a aplicação inteira mesmo quando apenas um  módulo sofre alterações.
	- Impossibilidade de escalar módulos individualmente.
